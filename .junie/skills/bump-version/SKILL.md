## Purpose

Perform a reliable version bump and CHANGELOG update for the **rdp-connector**
Tauri/Vue application, keeping every version-bearing file in sync and producing
a CHANGELOG entry that matches the project's established style.

---

## Key facts (memorize)

- The version lives in **three** files that must stay in sync:
  1. `src-tauri/Cargo.toml` — `version = "X.Y.Z"` under `[package]`.
  2. `src-tauri/tauri.conf.json` — top-level `"version": "X.Y.Z"`.
  3. `src-tauri/Cargo.lock` — the `[[package]]` entry whose `name = "rdp-connector"`.
- `package.json` is intentionally `"version": "0.0.0"` — **do not** touch it.
  It is not used for app versioning.
- The app footer reads the version at runtime via Tauri `getVersion()`, which
  resolves from `tauri.conf.json` — so `tauri.conf.json` is the source of truth
  for the displayed version.
- `CHANGELOG.md` is the human-edited changelog. `docs/changelog.md` is
  **auto-generated** from it via `npm run docs:prepare` — **never** edit
  `docs/changelog.md` by hand.

---

## Step 1 — Determine the target version

- If the user gave an explicit version (e.g. "bump to 1.4.0"), use it verbatim.
- Otherwise read the current version from `src-tauri/tauri.conf.json` and bump
  according to the requested scope (major / minor / patch). Ask the user if the
  scope is ambiguous.

---

## Step 2 — Update all three version files

Set the same `X.Y.Z` value in:

1. `src-tauri/Cargo.toml`
2. `src-tauri/tauri.conf.json`
3. `src-tauri/Cargo.lock` (only the `name = "rdp-connector"` package block)

Do not modify `package.json`.

---

## Step 3 — Gather changes for the CHANGELOG

1. Find the latest release tag:

   ```
   git tag --sort=-creatordate
   ```

   (Tag naming in this repo is inconsistent, e.g. `v1.3.2.1`, `v1.3.2`,
   `1.3.1` — take the newest by creator date.)

2. List the commits since that tag:

   ```
   git log --oneline --no-merges <lasttag>..HEAD
   ```

3. Translate commits into concise CHANGELOG bullets using the existing style:
   - Collapse all dependency-bump commits (`deps(...)`, `bump ...`,
     `update dependencies`) into a single `- update dependencies` line.
   - Record a FreeRDP version change as `- FREERDP_VERSION=X.Y.Z` (read the
     current value from `freerdp/Dockerfile`).
   - Keep feature/fix bullets short and imperative, matching neighbouring
     entries (e.g. `- add certificate dialog flow`, `- fix build`).
   - Always include a `- bump version to X.Y.Z` line.

---

## Step 4 — Write the CHANGELOG entry

Insert a new section at the **top** of `CHANGELOG.md`, directly under the
`# Changelog` heading, using this shape:

```markdown
## vX.Y.Z

- bump version to X.Y.Z
- <feature / fix bullets>
- update dependencies
- FREERDP_VERSION=X.Y.Z
```

Only include the `update dependencies` / `FREERDP_VERSION` lines when they
actually apply. Leave all older sections untouched.

Do **not** edit `docs/changelog.md`; it is regenerated by `docs:prepare`.

---

## Step 5 — Verify

Confirm the manifest and lockfile agree and report the expected version:

```
cargo metadata --manifest-path src-tauri/Cargo.toml --locked
```

It should succeed and report `rdp-connector@X.Y.Z`. A failure here usually
means `Cargo.lock` was not updated to match `Cargo.toml`.

For a version-/changelog-only change, the full frontend and backend test
suites do not need to run. If application code was also touched, run
`npm run test:frontend` and `npm run test:rust` per the project guidelines.

---

## Step 6 — Report

Summarize:
- the old → new version,
- the files changed,
- the CHANGELOG bullets added,
- the verification result.
